# 履修登録期間の判定と期間外の履修時間割

調査日: 2026-11-17（日本時間）

1つの学生アカウントで、通常のログインと読み取りだけを確認した。

- `StudentApp/Regist/RegistEditStart.aspx` をGETすると、期間外は `ctl00_phContents_ucRegistMessage_lblMessage_lbl` に「履修登録の期間内ではありません。」と表示される。ログイン後の1回のGETで判定でき、今回の一例では約20msだった。速度は保証しない。
- 期間中は入口から編集画面・確認依頼後の確認画面への転送と履修表を確認する。追加・削除ボタンの有無だけでは期間を判定しない。今回の実接続は期間外のみで、期間中・確認依頼後は保存済みの画面構造によるテストで検証した。
- トップページへの転送やメンテナンスなど、根拠が読めない応答は `unknown` にする。日付や全学共通の学年暦から本人の登録可否を推定しない。
- アプリは利用者ごとに確定結果を最大5分キャッシュする。ログイン・ログアウトで破棄し、画面側も5分間隔で再確認する。期間外・判定不能の間は履修登録タブを表示しない。

期間外に履修情報そのものが必要な場合は `StudentApp/Regist/RegistList.aspx` を使う。ただし、ログイン直後の直接GETはトップへ転送された。入口から、表示されている「履修・成績情報」→「履修時間割表」のメニューを、そのページのフォーム情報と `__doPostBack` の送信先を使ってたどると取得できた。メニューの要素番号は固定しない。

取得先がトップへ転送された場合などは、空の履修として返さずエラーにする。履修登録タブの期間外表示では履修一覧を取得せず、時間割と教務の履修時間割表へのリンクを案内する。

登録・削除・確認依頼の送信は行っていない。認証情報・Cookie・個人の履修一覧はこのメモには含めない。

## 成績・履修計画への反映

期間外の転送先を空の履修情報として返していたことが、履修中の必修科目を未修得と表示する原因にもなっていた。通常のメニュー遷移で取得した履修情報を必修照合・卒業研究の見通し・履修計画に共通して使う。

履修情報の取得失敗時は必修科目を確認不能とし、卒業研究の条件も判定を保留する。科目名による照合は組番号・空白・`I` / `Ⅰ` / `Ｉ` の表記差をそろえ、`Ⅰ` と `Ⅱ` は区別する。履修中の単位を修得済みにはしない。
